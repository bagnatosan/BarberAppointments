* ¿Cómo funciona el flujo técnico en .NET?
Para implementar esto, hay tres conceptos que tenés que entender antes de tocar una sola tecla:

1. Claims (Las Declaraciones)
Un Claim es un pedacito de información sobre vos. Por ejemplo:

"Mi nombre es Santiago"

"Mi ID de usuario es 45"

"Soy un Cliente" (Rol)

"Mi mail es santiago@ejemplo.com"

2. ClaimsIdentity & ClaimsPrincipal
ClaimsIdentity: Es el "Pasaporte". Es el conjunto de todos tus Claims agrupados en un documento oficial.

ClaimsPrincipal: Es el "Dueño del Pasaporte". Es el objeto que representa al usuario logueado en el código de C#.
 Vos le preguntás al User: "¿Che, tenés el claim de Nombre?".

Middleware de autenticacion:
Es un guardia que se para en la entrada de tu aplicación (Program.cs). 
Cada vez que llega una solicitud del navegador, este guardia busca si hay una cookie.
Si la hay, la desencripta, arma el ClaimsPrincipal y te lo deja servido en el controlador para que lo uses.

Persistencia:Cuando generamos la cookie, podemos configurar una propiedad llamada IsPersistent.
Si es False: La cookie muere cuando cerrás el navegador (sesión volátil).
Si es True: La cookie se guarda en el disco duro del usuario con una fecha de vencimiento (ej. 30 días). 
Aunque apagues la compu, cuando vuelvas a entrar, el navegador le mandará la cookie al servidor y seguirás logueado.

* Los Data Annotations son, básicamente,
"etiquetas" que le pegás a las propiedades de tus clases para decirle al framework cómo deben comportarse.

Validación de datos: Evitan que entre basura. Si le ponés [EmailAddress], el sistema se encarga de que tenga un @ y un .com.

Configuración de la Base de Datos: Le dicen a Entity Framework cómo crear las tablas. [Required] se traduce en un NOT NULL en SQL.


[Required]
[EmailAddress]
public required string Email { get; set; }
